1. Executive Summary
This product is an AI-powered Author Publishing OS: a multi-tenant SaaS where authors and publishing teams can upload or create manuscripts, improve them with AI and human collaborators, manage every asset, generate creative materials, produce professional editions, validate them against retailer rules, and export or publish through supported channels.
The architecture deliberately separates AI assistance from the canonical source of truth. PostgreSQL/Supabase stores durable business state; Redis handles transient infrastructure; Qdrant provides semantic retrieval; deterministic rendering and validation engines produce the actual publication packages.
1.1 Vision
Make professional book creation and publishing accessible from one workspace without sacrificing author control, accountability, quality or production rigor.
1.2 Mission
Turn a manuscript into a structured, editable and publishable book.
Reduce repetitive editorial and production work with AI.
Enable authors, editors, writers, illustrators and publishers to collaborate in one workspace.
Create professional file, folder, version and approval accountability.
Create network effects through author communities and referral credits.
Build a retailer-agnostic publishing engine whose rules can evolve as external platforms change.
2. Goals, Non-Goals & Success Criteria
2.1 Goals
Import supported DOCX, EPUB and TXT manuscripts while preserving originals.
Normalize content into a canonical Book Model.
Provide proofreading, copyediting, consistency, style and developmental assistance.
Maintain a searchable Book Bible using Qdrant-backed semantic retrieval.
Provide professional editing, comments, tasks, approvals and version history.
Provide folders, assets, versions, permissions, usage tracking and audit logs.
Generate illustrations and covers through pluggable image-generation providers.
Generate EPUB/PDF and validate output deterministically.
Support versioned retailer rules for KDP, Apple Books, Barnes & Noble, Lulu and future channels.
Provide community, moderation, referrals and an immutable credit ledger.
Provide a Flutter mobile companion for iOS and Android.
Provide subscription billing and usage metering.

6.1 Architecture Rules
Supabase/PostgreSQL is the transactional source of truth.
Qdrant is a retrieval index, never the source of truth.
Redis is ephemeral infrastructure; durable business state remains in PostgreSQL.
Original uploads are immutable; derived assets are versioned.
AI returns structured suggestions/operations and does not silently overwrite canonical content.
Publishing rules are versioned and independent of UI code.
Important mutations generate audit events.
Async jobs have idempotency, retries, status and observability.
Web and Flutter share backend contracts.
Tenant isolation is enforced server-side and, where applicable, with Supabase RLS.

8.1 DB Rules
UUID primary keys; UTC timestamps; foreign keys and appropriate indexes.
JSONB only for extensible metadata, not core relational fields.
Unique constraints for slugs, referral codes, version numbers and idempotency keys where applicable.
Transactions for credit ledger and entitlement changes.
RLS plus application authorization for tenant-sensitive records.
Soft-delete where recovery/legal requirements justify it.

12. Canonical Book Model
The Book Model is the central product abstraction. Semantic content is separated from rendering so one source can produce multiple editions.
Book ├─ Metadata ├─ Style Guide ├─ Book Bible ├─ Chapters[] │   └─ Nodes[] │      ├─ heading │      ├─ paragraph │      ├─ quote │      ├─ list │      ├─ image │      ├─ caption │      └─ page_break ├─ Assets[] └─ Editions[]     ├─ Ebook     └─ Print
The editor changes content through typed operations such as insert_node, update_node, move_node, replace_text, set_attribute and attach_asset. Original source files are never overwritten.

32. Final Product Recommendation
The strongest product is not merely an AI formatter. It is the system of record for a book's lifecycle: manuscript → structured content → editorial review → creative assets → editions → validation → publishing → archive.
The foundational moat should therefore be the Canonical Book Model, asset accountability, versioning, human-in-the-loop AI, semantic Book Bible, deterministic publishing engine and collaborative workspace.
Supabase + Redis + Qdrant + Next.js + TypeScript/Python + Flutter is a coherent first production architecture. The next engineering artifact should be a Master Build Specification containing exact SQL migrations/RLS, OpenAPI schemas, JSON schemas, Qdrant payloads, Redis job contracts, AI tool schemas, prompt/version rules, UI component contracts and dependency-ordered tickets.
